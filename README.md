# 传送带物体计数系统 — 使用手册

传送带/流水线上连续经过物体的**检测与计数**系统。纯 OpenCV 实现,**不依赖深度学习、不需要训练、不需要 GPU**。

适用场景:物体**单列经过、彼此不遮挡、与背景可区分**、大致匀速。配套合成数据生成与自动调参工具,可在无真实数据时先跑通全链路。

## 核心概念

**处理管线**
```
[相机采集 / gen_shapes_video]  →  .mp4 (+ _meta.json 真值)
        → [video_to_frames]  →  frames/  (逐帧图片)
        → [count_cv]         →  计数结果 (+ 标注视频)
                ↑ 参数
        [tune_params] → best_params.json  (用带真值样例搜出)
```

**模块职责(均为仓库根目录的扁平模块)**
- `sources.py`:输入源读取、帧解码与缩放。
- `params.py`:默认参数 `DEFAULT_PARAMS`、JSON 参数加载与参数校验/合并。
- `counting.py`:检测器 `Detector`、跟踪器 `Tracker` 与可复用入口 `count_source`。
- `count_cv.py`:只负责命令行解析、参数装配、调用 `count_source`,以及计数结果/真值/误差报告;核心功能应从上述模块导入,而不是从 `count_cv` 导入。

**检测/跟踪两阶段**(每帧)
```
检测 Detector: 前景分离 → 形态学去噪 → 轮廓 → 面积/形状过滤 → 粘连分割/碎裂合并 → 检测点
跟踪 Tracker:  全局最短距离匹配(速度预测) → 轨迹确认/方向门控 → 越线(可迟滞)计数
```

**前景分离(方式)**
| 方式 | 原理 | 适用 |
|------|------|------|
| `bgsub` | MOG2 背景建模,变化像素=前景 | 背景视觉均匀/静止;**多模态,能扛住周期性移动纹理**(带子花纹滚动) |
| `color` | HSV 饱和度阈值 | 彩色物体 + 灰背景(灰纹理无饱和度,不受其运动影响) |
| `thresh` | 灰度强度阈值:亮度在背景带 `[lo,hi]` 之外=前景 | **物体亮度明显区别于纹理带**;无状态、最快、免疫任意纹理运动 |
| `refbg` | 减一张"空传送带"基准图 | 能拿到无物体背景;**仅静态背景**(移动纹理会失效) |
| `auto` | 按高饱和像素占比自动在 color/bgsub 间选 | 默认(不会选 thresh/refbg) |

**计数原理**:每条轨迹的质心**穿过一条虚拟线**时计一次(每条轨迹只计一次)。

## 脚本 1:gen_shapes_video.py — 合成数据生成

生成传送带风格视频:不规则圆/三角/方/矩形,可控运动与成像退化,自带真值。

```bash
python3 gen_shapes_video.py -o belt.mp4 --gray --fps 120 --speed 5000 \
    --count 6 --duration 10 --motion-blur 7 --noise 4 --labels labels
```

### 参数
| 参数 | 默认 | 说明 |
|------|------|------|
| `-o, --output` | belt.mp4 | 输出视频路径 |
| `--duration` | 15 | 时长(秒) |
| `--fps` | 30 | 帧率 |
| `--width` `--height` | 1280 / 720 | 分辨率 |
| `--count` | 6 | 画面中**同时**存在的物体数(约) |
| `--speed` | 500 | 移动速度(px/秒) |
| `--direction` | l2r | 方向:l2r/r2l(横)、t2b/b2t(竖) |
| `--gray` | 关 | 灰度模式(物体靠亮度区分,均匀灰底,贴近工业相机) |
| `--noise` | 0 | 高斯传感器噪声标准差 |
| `--motion-blur` | 0 | 运动模糊核大小(奇数,沿运动方向;0=关) |
| `--min-size` `--max-size` | 28 / 48 | 物体半径范围(px) |
| `--deform` | 0.22 | 形状变形量(顶点扰动,0~0.5) |
| `--wobble` | 0 | 逐帧形状抖动幅度(模拟软性物体;0=关) |
| `--outline` | 关 | 给物体加黑色描边 |
| `--labels DIR` | 无 | 导出 YOLO 逐帧标注到 DIR |
| `--seed` | 0 | 随机种子(复现) |
| `--debug` | 关 | 打印每次越线真值事件 |

### 产出
- `belt.mp4` — 视频
- `belt_meta.json` — 真值:`crossed_center_line`(越过中线总数)、`total_spawned`、速度/密度等
- `labels/frame_*.txt` — (若 `--labels`)YOLO 格式 `类别 cx cy w h`(归一化)

## 脚本 2:video_to_frames.py — 视频转图片

视频 → `frame_000000.jpg` 序列(工业逐帧落盘形态),并把真值 json 拷进文件夹。

```bash
python3 video_to_frames.py belt.mp4 frames_belt --ext jpg
```

| 参数 | 默认 | 说明 |
|------|------|------|
| `video` `out_dir` | — | 输入视频 / 输出文件夹(位置参数) |
| `--ext` | jpg | 图片格式 jpg/png(png 无损,jpg 省空间) |
| `--step` | 1 | 每隔 N 帧抽一张 |
| `--start` `--end` | 0 / -1 | 起始/结束帧(-1 到末尾) |
| `--quality` | 95 | jpg 质量(1-100) |

> 图片文件名**零填充**(frame_000001),保证按字典序=时间序。

## 脚本 3:count_cv.py — 命令行入口

`count_cv.py` 是计数功能的 CLI 入口,输入可以是**视频文件**或**图片文件夹**;灰度/彩色**自动识别**。

**支持的输入格式**
- **视频**:走 OpenCV 解码,支持 mp4/avi/mov/mkv/webm/m4v/flv 等常见格式(取决于系统 ffmpeg)。
- **图片文件夹**:jpg/jpeg/png/bmp/tif/tiff/webp/ppm/pgm 等;文件名**自然排序**(`frame2` 排在 `frame10` 前,非零填充命名也正确)。

```bash
python3 count_cv.py <视频或文件夹> --save out.mp4                  # 最简
python3 count_cv.py frames_belt --method refbg --roi 0,200,1280,520 \
    --min-area 200 --max-dist 180 --save out.mp4 --save-fps 20

# 读取调参结果
python3 count_cv.py clip.mp4 --params best_params.json

# 显式命令行参数覆盖 JSON 中的同名值
python3 count_cv.py clip.mp4 --params best_params.json --min-area 180
```

参数优先级从低到高为:`DEFAULT_PARAMS` < `--params` 指定的 JSON < 显式命令行参数。只有实际写在命令行上的参数才会覆盖 JSON;未显式指定的参数继续采用 JSON 或默认值。


### 前景分离参数
| 参数 | 默认 | 说明 / 何时调 |
|------|------|--------------|
| `--method` | auto | auto/bgsub/color/thresh/refbg(见[核心概念](#核心概念)) |
| `--sat-thresh` | 60 | color 模式饱和度阈值;物体颜色淡→调低 |
| `--thresh-lo` `--thresh-hi` | 50 / 205 | thresh 模式:亮度 `<lo` 或 `>hi` 判为前景(背景带在 `[lo,hi]` 内)。亮物体调 hi、暗物体调 lo |
| `--bg-history` | 200 | MOG2 背景建模历史帧;背景变化快→调小 |
| `--bg-var` | 40 | MOG2 前景灵敏度;噪声多→调大,漏检→调小 |
| `--ref-thresh` | 25 | refbg 灰度差阈值;物体与背景亮度差小→调低 |
| `--bg-ref` | auto(帧中位数) | refbg 基准图路径;有空传送带图就填 |
| `--ref-alpha` | 0(静态) | refbg 参考帧慢更新系数;光照缓慢漂移→设 0.01~0.05 |

### 检测过滤参数
| 参数 | 默认 | 说明 / 何时调 |
|------|------|--------------|
| `--min-area-frac` | 0(关) | **最小面积占画面比例**(0~1);**推荐直接用**:分辨率/缩放无关,知道物体占画面多大就填 |
| `--max-area-frac` | 0(不限) | **最大面积占画面比例**(0~1);优先级高于像素值 |
| `--min-area` | 300 | 轮廓最小面积(**像素**);未设比例时用。小于则当噪声丢弃 |
| `--max-area` | 0(不限) | 轮廓最大面积(像素);滤超大背景块/粘连 |
| `--max-aspect` | 0(不限) | 最大长宽比;滤细长噪声条纹(如设 5) |
| `--morph-kernel` | 7 | 形态学核大小(奇数);噪声大→调大,小物体→调小 |
| `--morph-iter` | 2 | 闭运算迭代;物体有空洞/断裂→调大 |
| `--split-area` | 0(关) | 面积超此值的大块触发**粘连分割** |
| `--unit-area` | 0 | 单个物体典型面积;拆分个数=块面积/unit-area(假设物体大小相近) |
| `--merge-dist` | 0(关) | 合并质心距离小于此值的检测,**修复单物体碎裂→重复计数** |
| `--roi` | 无 | 只处理 `x0,y0,x1,y1`,忽略传送带边缘/无关区。**先裁后算,能按比例提速**——计数只需看计数线附近一条带 |
| `--scale` | 1.0 | 处理前缩放;<1 加速大图。**注意面积/ROI 按缩放后像素**(scale 0.5→面积/4) |

### 跟踪 / 计数参数
| 参数 | 默认 | 说明 / 何时调 |
|------|------|--------------|
| `--max-dist` | 140 | 预测位置与检测的最大匹配距离;**高速必须 ≥ 每帧位移**(=速度/帧率) |
| `--track-ttl` | 5 | 轨迹漏检后存活帧数;短暂遮挡/闪断→调大 |
| `--min-hits` | 1 | 轨迹须**连续观测 N 帧**才允许计数;任一漏检间隙会重新开始连续确认,但 `track-ttl` 仍可保留该轨迹及其运动历史。噪声闪现误计→调到 2~3 |
| `--min-speed` | 0(关) | 计数所需最小轴向速度(px/帧);排除静止噪声 |
| `--line` | 0.5 | 计数线位置(画面比例,沿计数轴) |
| `--line-band` | 0 | 迟滞带宽(画面比例);物体在线附近抖动重复计→设 0.03~0.05 |
| `--axis` | x | 计数轴:x=横向传送带,y=竖向 |
| `--flow` | both | 计数方向:pos(坐标增大 l2r/t2b)/neg(减小 r2l/b2t)/both |
| `--warmup` | 8 | bgsub 前若干帧只建模不计数(等背景收敛) |

### 输出参数
| 参数 | 默认 | 说明 |
|------|------|------|
| `--save PATH` | 无 | 保存标注**视频** |
| `--save-fps` | 源帧率 | **标注视频播放帧率**;不丢帧,低于源帧率=慢放(高帧率视频回看必备,如 120fps 源设 20) |
| `--save-frames DIR` | 无 | 保存标注帧为**图片序列**到 DIR(契合图片文件夹工作流;可与 `--save` 同时用) |
| `--show` | 关 | 实时显示窗口(ESC 退出) |
| `--fps` | 30 | 图片文件夹模式的帧率(仅影响保存时间轴) |
| `--meta PATH` | 自动查找 | 计数真值 json;有则打印误差 |
| `--debug` | 关 | 打印每次计数事件 |
| `--profile` | 关 | 逐帧打印**处理耗时**(仅检测+跟踪,不含读帧)+ 结尾统计:平均/中位/p95/最大、有效吞吐 fps、能否跟上源帧率(实时判定) |

### 标注视频图例(用于人工核对)
- 🟩 **绿框** = 每帧检测到的物体
- 🟥 **红线** = 计数线
- 🔵 **青色数字** = 轨迹 ID(同一物体全程同号)
- 🟡 **黄点** = 该轨迹**已计数**(越线瞬间点亮)
- 左上 = 实时累计数

**核对方法**:每个物体穿过红线时是否恰好点亮黄点、计数器 +1,且同一物体不重复点亮。

## 脚本 4:tune_params.py — 自动调参

给带"总数"的样例,网格搜索最佳参数。**真值只需每段总数**,不用标框。

```bash
# samples.txt 每行: 路径[,总数]  (留空则从 *_meta.json 自动取)
python3 tune_params.py samples.txt --axis x --flow both --scale 0.5 --jobs 4
python3 tune_params.py samples.txt --val val.txt \
    --grid '{"min_area":[60,120,200],"bg_var":[15,30,50],"max_dist":[120,180]}'
python3 tune_params.py samples.txt --method thresh --scale 0.5
```

### 清单格式
```
# 井号注释。三种写法:
frames_a, 120        # 图片文件夹 + 显式真值
clip_b.mp4, 86       # 视频 + 显式真值
clip_c.mp4           # 留空 → 自动读 clip_c_meta.json 的 crossed_center_line
```

### 参数
| 参数 | 默认 | 说明 |
|------|------|------|
| `manifest` | — | 样例清单(位置参数,必需) |
| `--val` | 无 | 验证集清单(同格式,不参与搜索,只评泛化) |
| `--grid` | 内置 | 自定义网格 json,如 `'{"min_area":[100,200],"bg_var":[30,50]}'` |
| `--axis` `--flow` `--method` `--line` `--scale` `--roi` | 用默认 | **固定场景参数**(不搜索),设成现场实际值;`--method thresh` 受支持 |
| `--jobs` | 1 | 并行进程数(按样例) |
| `--mem-mb` | 2000 | 每段帧缓存内存上限;超出自动逐帧重读(内存安全) |
| `--topk` | 10 | 展示前 K 组 |
| `--out` | best_params.json | 最佳参数输出 |

> 缓存模型要求影响帧准备/检测缓存含义的参数在一次搜索中保持固定。自定义 `--grid` 因此会拒绝 `method`、`scale`、`bg_ref`、`axis`;其中可用的命令行选项应作为上表所列固定参数传入,而不是放进网格。

### 打分与选参
- **SAE** = 所有样例绝对误差之和(越小越好)。
- **BIAS** = 带符号误差之和,**暴露"漏检/误检互相抵消"**:全负=系统性漏检(该扩小 min_area 等),全正=误检。
- **平台中心选参**:多组并列最优时,选四周邻居也都最优的那组(**离失败边界最远、最鲁棒**),而非任意/最激进取值。

### 产出
`best_params.json`(完整参数,可直接喂 count_cv)+ 打印可套用的命令行。

## 调参速查表(症状→调哪个参数)

| 症状 | 优先调整 |
|------|---------|
| **少数**(漏计) | ↓`min-area`、↓`bg-var`、↓`min-hits`、↑`max-dist`(高速)、检查 `line` 是否在物体必经处 |
| **多数**(误计) | ↑`min-area`、↑`bg-var`、↑`min-hits`、设 `max-aspect`、设 `line-band` |
| 同一物体被数多次 | 设 `line-band` 0.03~0.05、↑`merge-dist`(碎裂)、↑`track-ttl` |
| 两个物体数成一个 | 开 `split-area`+`unit-area`、↓`morph-iter`/`morph-kernel` |
| 高速漏计/轨迹断 | ↑`max-dist`(≥每帧位移)、提高相机帧率 |
| 背景杂/噪声多 | 换 `--method refbg`、↑`bg-var`、↑`morph-kernel`、设 `--roi` |
| 光照缓慢变化漏检 | `refbg` + `--ref-alpha 0.02` |
| 处理太慢 | `--scale 0.5`(记得同步调小 min-area)、`--roi` |
| 反向/竖向传送带 | `--flow neg`/`--axis y` |
| 不确定怎么调 | 直接用 `tune_params.py` 搜 |

## 输入要求与假设

**必须满足(否则不准)**
- 物体**单列、彼此有间隙**、**不互相遮挡**
- 背景**相对干净、稳定**;物体与背景**可区分**(灰度靠亮度、彩色靠饱和度)
- 相机**固定**、光照**大致恒定**(漂移用 refbg+ref-alpha)
- **每帧位移 = 速度/帧率 < 物体尺寸 且 < 物体间距**(否则采样混叠)

**速度—帧率对照(物体约 60px)**
| 速度 | 需要帧率 |
|------|---------|
| ≤ 300 px/s | 30fps |
| ~10000 px/s | ~200fps(实测 0 误差) |
| ≥5000 px/s 且密集 | 更高帧率 + 短曝光/频闪冻结运动 |

**面积要求**:物体表观面积须落在 `[min-area, max-area]` 内;**各物体面积不必相同**(仅"粘连分割"假设大小相近)。**推荐用 `--min-area-frac`/`--max-area-frac` 按占画面比例指定**——分辨率和 `--scale` 都无关,直接填即可、无需调参。

## 已知限制

- **采样混叠 / 运动模糊**:物理限制,软件不可解,需高帧率 + 短曝光/线阵相机。
- **粘连/乱序/多列**:超出"单列不遮挡"假设时精度下降(`split-area`/`merge-dist` 仅部分缓解)。
- **匀速假设**:跟踪用恒速预测,剧烈变速会失准。
- **总数调参是弱信号**:样例需覆盖真实工况,否则过拟合(用 `--val` 检查)。
- 极高速纯计数场景,**光电传感器**往往比视觉更实际可靠。

## 常见问题排错

**Q: `count_cv` 报"文件夹中没有图片"**
A: 图片扩展名需为 jpg/jpeg/png/bmp,且文件名可排序。

**Q: 计数一直是 0**
A: 检查 `--flow`/`--axis` 方向是否对;`--line` 是否在物体经过区;前景是否分离成功(先 `--save` 看绿框有没有)。

**Q: bgsub 前几帧疯狂误检**
A: 正常,`--warmup` 会跳过前若干帧建模期;可适当调大。

**Q: 标注视频太快看不清**
A: `--save-fps 20`(或更低),不丢帧、慢放回看。

**Q: 背景有纹理(带子表面有花纹)怎么办**
A: 静态纹理:`bgsub`/`refbg` 会学成背景。**移动纹理**(花纹随带子滚动):优先 `bgsub`——MOG2 多模态能学会反复出现的纹理,实测高对比滚动纹理也 0 误差;`refbg` 会失效(单张参考配不上移动纹理)。若物体亮度明显区别于纹理带,用 `--method thresh --thresh-lo/--thresh-hi` 最稳(无状态、免疫任意纹理运动)。若纹理与物体亮度/颜色都相近,视觉难分离,需换线阵相机或调光。

**Q: 处理跟不上相机实时帧率怎么办**
A: 先用 `--profile` 看每帧处理耗时和有效吞吐;若 p95 超过每帧预算(1000/源fps ms),用 `--scale 0.5`(配 `--min-area-frac`/`--max-area-frac` 免调)、`--roi` 缩小处理量。实测 1280×720 全分辨率约 240fps,`--scale 0.5` 后约 470fps;**用计数线附近细带 `--roi`(如 `540,0,740,720`)约 390fps**——计数只需看越线区,先裁后算按比例省。

**Q: `--scale 0.5` 后突然漏检很多**
A: 绝对 `--min-area` 是像素,缩放后面积缩 4 倍会被误滤。**改用 `--min-area-frac`/`--max-area-frac`(占画面比例)即可免调**,缩放无关。

**Q: 高速视频轨迹乱跳/漏计**
A: `--max-dist` 调到 ≥ 每帧位移(速度/帧率);仍不行说明帧率不足。
